# ARC promotion release review — 14 October 2026

Per-purchase recovery replaces one pending slot per token. Captured older boosts can complete after newer ones without lowering observed totals. Pending boosts expire after 30 minutes and are bounded at 100; the delivered identity cache is also capped at 100. Every protected boost checkpoint write must be acknowledged before attempting fan-out. Missing checkpoint reads and failed reads are distinct.

DEX uses every eligible timestamp from the existing orders response, capped at 24 pending purchase identities. It processes at most one payment per token and two tokens per existing 30-second scan. A watched old payment must remain in the current eligible response; cancelled, removed or malformed orders cannot be authorized by another payment. Security remains mandatory; custom zero/missing sells remain watched. LP warnings and verified PONS exemption are unchanged. Prior-confirmed recipients count as confirmations, not new Telegram sends; no recipients cannot close a boost.

The shared existing health snapshot now includes an opaque, bounded 128-event/hour audit with distinct stages and explicit evictions/expiry. No raw token payloads, recipients, SQL audit writes, new poller or service. Redis readiness handling now uses the already-tested main worker implementation. The diagnostic window resets with each worker; published snapshots expire after one hour. It is a recent bounded observation window, not an exhaustive upstream census.
